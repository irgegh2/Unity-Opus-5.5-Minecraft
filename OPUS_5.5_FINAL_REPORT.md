# OPUS_5.5_FINAL_REPORT.md

Final report for the "recreate Minecraft Java in Unity" run (project `MCR`, Unity 6000.6.0f1, URP 17.6,
Input System). Numbers come from the game's own registries (`AutoTest.WriteReport`), the build output,
the EditMode test results, the files on disk and the Claude Code session transcripts at the end of the
run. Status per feature: `FEATURE_MATRIX.md`; build, tooling and controls: `DEVELOPMENT.md`.

## 1. What was built

A single-player Minecraft-like game written from scratch in C#: 115 runtime scripts (51,859 lines),
3 editor scripts (1,059 lines), 1 EditMode test fixture (9 tests), 6 custom shaders (457 lines) and a
Python tool chain (8 scripts, 1,433 lines: fast compile check, Blender bridge, FBX/item pipelines,
token accounting). The scene contains only a bootstrap; every world, texture, model, icon, sound and UI
element is generated by the project's own code or its editor/Blender pipeline.

* **World:** streamed 16³-section chunks with threaded generation, 3-layer meshing, smooth sky/block light;
  noise terrain from y −64 to 320, caves, ores, 56 biomes, 28 tree/feature types; Nether (5 biomes) and End
  (island, pillars, crystals, gateways, outer islands); 20 structure types, all generating (village,
  stronghold with portal room, mineshaft, temples, outpost, mansion, ancient city, trial chambers, ruined
  portals, shipwrecks, Nether fortress, bastion, End city ...).
* **Gameplay:** Creative (default) and Survival, Normal difficulty by default; mining with tool tiers,
  908 crafting + smelting recipes (+175 stonecutting, 10 smithing), furnaces, brewing (44 potions),
  enchanting (43 enchantments), anvil, grindstone, trading, farming, hunger, melee/ranged combat, 36 status
  effects, XP, redstone (dust, repeaters, comparators, pistons, observers, hoppers, dispensers, rails ...),
  TNT and explosions, boats/minecarts/rideable animals, Nether and End portals, the Ender Dragon fight with
  exit portal, egg, gateways and credits, the Wither, the Warden; 26 commands + 9 aliases with Tab
  completion and `~` coordinates; F3 debug overlay and combos including F3+F4.
* **Content:** 896 blocks, 1268 items, 89 mobs with spawn eggs for every mob and boss, 105 articulated
  models, 1552 procedural texture layers (0 missing), 40 advancements with toasts.
* **Interface:** own immediate-mode UI (bitmap font, code-painted sprite atlas, meshes rendered into a
  texture): title screen with a rotating world panorama, world list/creation with seed input, options
  (persisted, including volumes), pause, death, chat, credits; survival HUD with half hearts, containers,
  armour row and fire overlay; survival inventory with a 3D player preview that follows the mouse;
  16 container menus; searchable creative inventory with 13 tabs including a Survival Inventory tab.
* **Persistence:** per-dimension region files storing only changed blocks, block entities and entities;
  player, inventory, time, weather, rules, dragon fight and Nether portal links; autosave every 60 s and on
  window close.
* **3D asset pipeline (Blender MCP `blender_unity`, port 9876, `UnityMinecraft.blend`):** 105 mob/prop
  models (player, 89 mobs, dragon, Wither, boats, minecarts, chests, End crystal, shield, trident, spear,
  bow, crossbow, armour) + 45 held-item meshes + 6 props (torch, soul torch, lantern, soul lantern,
  campfire, soul campfire) built in Blender, exported to 156 FBX files, imported by
  `Tools > Opus 5.5 Minecraft > Rebuild Generated Assets` and rendered at runtime (procedural fallback per
  model).

## 4. How to launch

* Player build: double-click `MinecraftRecreation.exe` in the project folder (the files beside it, such as
  `MinecraftRecreation_Data/` and `UnityPlayer.dll`, belong to it). New worlds start in Creative; choose Survival on
  the Create New World screen or with `/gamemode survival`.
* Editor: open the project in Unity 6000.6.0f1, open `Assets/_Game/Scenes/Main.unity`, press Play.
  `Tools > Opus 5.5 Minecraft > Rebuild Generated Assets` regenerates textures, models and imports.

## 5. Controls (summary)

WASD move, mouse look, Space jump (double-tap: fly in creative), Left Shift sneak, Left Ctrl or double-tap W
sprint, left mouse attack/mine, right mouse use/place, middle mouse pick block, wheel or 1-9 hotbar, E
inventory (creative screen in creative), Q drop (Ctrl+Q stack), F swap offhand, T chat, `/` command,
L advancements, Esc pause, F1 hide GUI, F2 screenshot, F3 debug (+B/G/A/D/N/T/Q, F3+F4 game-mode switcher),
F5 camera, F11 fullscreen, Ctrl+S save. Full table in `DEVELOPMENT.md` §10.

## 6. Known gaps and limitations

Complete list with evidence in `FEATURE_MATRIX.md`; the most visible:

1. Missing systems: raids, ocean monuments, recipe book, waterlogging, signs, banners (loom unusable),
   cake, leads, item frames, paintings, armour stands, maps/cartography, tripwire, Hardcore mode.
2. Model/visual defects: blaze rods and guardian spikes overlap, iron golem limbs static, enderman's carried
   block and the Wither's armour phase not shown, no guardian beam, placeholder shulker bullet and evoker
   fangs, dragon jaw never opens, no purple portal overlay, no natural lightning or snow build-up.
3. 13 of 40 advancements only via command; 10 of 36 effects and 5 of 43 enchantments have no effect;
   `opOnly` is never enforced; the credits roll on every exit from the End.
4. Player-lit TNT drops only ~1/power of the destroyed blocks (`Game/Explosion.cs`).
5. Blender is used to build and export the code-defined geometry (cuboid models, voxel item extrusions,
   props); no model is hand-sculpted in Blender.

## 8. Token usage and cost method

Source: the real API usage blocks recorded by Claude Code in this project's local session transcript
(first record 2026-09-23 16:05:57 +0200) and its 10 subagent transcripts, summed by
`python Tools/token_usage.py <session_jsonl> --until 2026-09-25T03:33:00Z --json Tools/_out/token_usage.json`. The cutoff is the
end of the project work: the counts include the final commit and summary, which ran until 05:32:34 +0200. A
response split over several transcript lines shares one message id, so usage is counted once per id (no
cumulative snapshots are involved); synthetic error records carry no usage.

* Requests: 1,957, all `claude-opus-5-5` (main session + 10 subagents), standard speed, global routing.
* `input_tokens` excludes cache reads and cache writes, so the three input classes are disjoint: uncached input =
  `input_tokens`, cached input = `cache_read_input_tokens`, cache writes = `cache_creation_input_tokens` (all of
  them to the 5-minute cache). Reasoning tokens are included in `output_tokens` and not reported separately.
* Rates: Claude Opus 5.5 on the Claude API (platform.claude.com/docs/en/about-claude/pricing, checked
  2026-09-25), USD per 1M tokens: $4.00 input, $5.00 5-minute cache writes ($8.00 for the 1-hour cache, not
  used), $0.20 cache hits, $20.00 output. The full 1M context window is billed at standard rates, so there is no
  long-context adjustment. Tool fees are not included; the figure is a token-only API equivalent, not a bill.
* Cost: input 3,916 x $4 = $0.02; cache writes 59,635,523 x $5 = $298.18; cache reads 606,627,431 x $0.20 =
  $121.33; output 3,729,536 x $20 = $74.59; total **$494.11**.
* Active working time: the model responses and tool results of all agents on one timeline; gaps of up to 30
  minutes count as work (Unity builds, long generations), longer silences and the stalls around API errors count
  as pauses. The rest of the wall-clock time went to usage-limit stops (HTTP 429), waiting for the next
  "continue", and a 41-minute API outage (HTTP 503). The subagents worked in parallel with the main session:
  counted separately, their busy time adds about 9.9 hours to the main session's 10.2 hours.
